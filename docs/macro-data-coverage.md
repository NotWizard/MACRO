## 本轮确认的源侧问题

1. `data.stats.gov.cn` 在 2026-10-25 对程序请求返回 CWAP WAF 302；
   `macro_china_nbs_nation()`、`macro_china_urban_unemployment()` 可能返回 HTML。
2. `www.stats.gov.cn/sj/zxfb/` 静态发布归档可用，因此 PMI 分项与房地产活动改为解析官方 HTML 表。
3. AKShare/Jin10 的 RatingDog（原财新）PMI 停在 2025-09。2026-06 至 2026-09 已按
   S&P Global 发布值补齐；2025-10 至 2026-05 的免费历史中段仍缺。
4. 东财财政收入的累计口径与 NBS 一致；支出当前月使用财政部发布值补齐，历史仍优先 NBS。
5. 东财海关金额原始单位在 fetcher 中除以 `1e5` 转为亿美元；只填 NBS 空值。

## 尚未补齐及原因

| 缺口 | 原因 | 处理 |
|---|---|---|
| RatingDog PMI 2025-10 至 2026-05 | 旧免费 API 停止，官方历史未提供开放批量接口 | 保持真实缺口；每月追加已确认发布值 |
| 全国 70 城价格广度 | 抓取与存储成本高于当前个人看板需求 | 当前显示 10 城，评分说明明确标注 |
| 地方债发行、信用-to-GDP gap | 与现有存量杠杆口径不同，需单独建表与定义 | 不混入现有债务图；后续独立设计 |
| 年龄中位数、迁移/户籍结构 | 现有 NBS route 不稳定，WB 年频更新较慢 | 已有 65+ 与抚养比，暂不重复堆叠 |

## 校验

- 每张新表均在 `scripts/_pipeline.py` 注册最小行数、必需列、合理区间和最长陈旧天数。
- 表面向 API 的 `/table/{name}` 白名单显式登记。
- `scripts/nbs_release.py` 只解析结构化发布表；任何表缺失都抛错，让闸门保留上一份好数据。
- 每次采集仍走 staging → validate → atomic replace，不接受部分源静默覆盖完整历史。
